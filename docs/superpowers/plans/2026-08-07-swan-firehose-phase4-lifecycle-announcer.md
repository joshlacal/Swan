# Swan Firehose Phase 4: Lifecycle Integrations, requestCrawl Announcer, and Operator Force-#sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Phase 1–3 firehose real: wire the four confirmed lifecycle operations (activation, rotation, status change, permanent deletion) to lifecycle-event emission, fix the deletion-gap lag entry gate first, add the `requestCrawl` announcer service, and add an operator CLI force-`#sync`.

**Architecture:** The batch model, per-DID generation barriers, sequencer, and deletion-marker primitive all exist and are tested; every task here connects a real operation to `enqueueLifecycleEventBatch` / `enqueuePublicFirehoseEvent` at the seam the design names. `SwanAccounts` cannot see `SwanSQLite`, so emission crosses the boundary through a new `PublicLifecycleEventEmitting` protocol in `SwanStorage`, implemented by `SQLitePublicLifecycleEmitter` in `SwanSQLite`. Commit rows stop hardcoding generation `0` and stop enqueueing for non-active accounts via a control-plane fence held around the (network-free) repository mutation. The announcer is a ServiceLifecycle peer of the retention pruner with per-crawler persistent backoff state in `control.sqlite`.

**Tech Stack:** Swift 6 strict concurrency, actors, XCTest, SQLiteNIO, Hummingbird 2.25.1, hummingbird-websocket 2.7.0, swift-service-lifecycle, AsyncHTTPClient 1.36.0, `jj`.

## Global Constraints

- **Entry gate:** the deletion-gap-aware lag fix (Task 1) MUST be committed before the permanent-deletion emission (Task 6) is wired. Do not reorder.
- **Unconditional enqueue, gated drain:** lifecycle batches and account-outbox rows are enqueued by real operations REGARDLESS of `--enable-public-firehose`; only sequencing, WebSocket serving, and the announcer are gated by the flag (matching the existing flag help text: rows "accumulate durably and drain once this flag is enabled").
- **Feature flag:** `--enable-public-firehose` remains default-off. Changing the default is a separate activation decision.
- **Emission ownership:** lifecycle events are emitted by the higher-level confirmed operation. `installPublicPLCOperation` and bare `transitionStatus` (i.e. calls that pass no emission descriptor) emit nothing. Restore/import/genesis paths emit nothing.
- **Source keys:** every source key is built by `PublicFirehoseSourceKey` helpers — never by string interpolation at a call site.
- **Frame material:** lifecycle payloads are JSON-encoded `PublicFirehoseIdentityMaterial` / `PublicFirehoseAccountMaterial` / `PublicFirehoseSyncMaterial`; times use `PublicFirehoseTime.encode(_:)` (`2026-08-04T12:00:00.000Z` format). The sequencer's existing decoder is the contract.
- **Deletion markers:** only the sequencer derives `FirehoseDeletionMarker` (from a decoded `active: false, status: .deleted` account item). No new derivation site.
- **SQLite:** every database operation uses `connection.query(sql, bindings)` inside `withConnectionGate` and, for writes, `transaction`; no network, WebSocket, or HTTP I/O occurs inside a SQLite transaction. The announcer performs HTTP strictly outside transactions.
- **Concurrency/style:** Swift 6 strict concurrency, actors for shared mutable state, 2-space indentation in `Sources/Swan*`/4-space in `Sources/swan` (match each file's existing indent), XCTest (not Swift Testing).
- **Wire compatibility:** no changes to frame encoding, `subscribeRepos` behavior contracts, or the public wire profile. `Profiles/public-data-testing-2026-08-06.json` and all predecessors stay byte-identical; no new profile is created this phase (nothing served changes — `requestCrawl` is an outbound client call).
- **Dependencies:** keep `hummingbird` exact `2.25.1`, `hummingbird-websocket` exact `2.7.0`, `async-http-client` exact `1.36.0`. No new packages.
- **Generator:** do not change or repin `Petrel-swan-generator`; no generated Swift source is hand-edited.
- **Workspace:** work only from `/Users/joshlacalamito/Developer/Catbird+Petrel/.worktrees/swan-public-federation`.
- **VCS:** use `jj`, not Git; commit only the files belonging to the current task. Never commit `.interop-cache`.

Defaults this plan fixes (the spec left them as ranges): announcer update-trigger throttle **15 minutes**; announcer periodic refresh **24 h**; announcer failure backoff `min(3600 s, 30 s × 2^min(attempts, 7))` with ±20 % jitter; announcer HTTP timeout **10 s**; status-change emission operation IDs are lowercased UUID strings generated by the calling operator entry point.

```swift
/// Counts stored (deliverable) rows strictly above `seq`, stopping at
/// `limit`. Per-DID deletion pruning leaves sequence-number gaps, so
/// `maxSequencedSeq() - cursor` overstates a consumer's real backlog; this
/// bounded count is the gap-aware measure the slow-consumer policy uses.
public func deliverableEventCount(after seq: Int64, limit: Int64) async throws -> Int64 {
  guard seq >= 0, seq <= FirehoseFrameLimits.maximumSequence else {
    throw SQLiteFirehoseDatabaseError.invalidCursor
  }
  guard limit >= 1 else {
    throw SQLiteFirehoseDatabaseError.invalidCursor
  }
  return try await withConnectionGate {
    let rows = try await connection.query(
      """
      SELECT COUNT(*) AS deliverable FROM (
        SELECT 1 FROM firehose_events WHERE seq > ? LIMIT ?
      )
      """,
      [.integer(Int(seq)), .integer(Int(limit))]
    )
    guard let value = rows.first?.column("deliverable")?.integer else {
      throw SQLiteFirehoseDatabaseError.corruptMeta
    }
    return Int64(value)
  }
}
```

Match the file's actual error-case names (`invalidCursor`/`corruptMeta` — reuse whatever `events(after:limit:)` and `maxSequencedSeq()` throw for the analogous conditions) and its exact row-decoding idiom.

```swift
public struct PublicFirehoseCommitFence: Sendable {
  private let control: SQLiteControlDatabase
  public init(control: SQLiteControlDatabase) { self.control = control }

  /// Applies `mutate` while holding the control-plane authorization
  /// transaction so no lifecycle transition can interleave with the
  /// generation snapshot. An account that no longer authorizes falls back
  /// to a non-emitting mutation (pre-activation and post-deactivation
  /// commits produce no firehose event).
  public func apply(
    did: String,
    mutate: @escaping @Sendable (PublicFirehoseCommitContext?) async throws
      -> CommittedPublicRepositoryMutation
  ) async throws -> CommittedPublicRepositoryMutation {
    do {
      return try await control.withActiveAccountFirehoseAuthorization(did: did) { generation in
        try await mutate(.init(lifecycleGeneration: generation))
      }
    } catch let error as AccountControlStoreError {
      guard case .invalidTransition = error else { throw error }
      return try await mutate(nil)
    }
  }
}
```

```swift
import Foundation
import SwanPublicFirehose
import SwanPublicRepository
import SwanStorage

public enum PublicLifecycleEmitterError: Error, Equatable {
  case accountUnavailable(String)
  case missingRepositoryHead(String)
  case missingCommitBlock(String)
}

public struct SQLitePublicLifecycleEmitter: PublicLifecycleEventEmitting {
  private let control: SQLiteControlDatabase
  private let accounts: any PublicFirehoseAccountDatabaseSource

  public init(
    control: SQLiteControlDatabase,
    accounts: any PublicFirehoseAccountDatabaseSource
  ) {
    self.control = control
    self.accounts = accounts
  }

  public func emitActivation(
    did: String, operationID: String, plcOperationCID: String,
    handle: String?, now: Date
  ) async throws {
    let time = PublicFirehoseTime.encode(now)
    let encoder = JSONEncoder()
    let identity = LifecycleEventItem(
      sourceKey: PublicFirehoseSourceKey.identity(did: did, plcOperationCID: plcOperationCID),
      kind: .identity,
      payload: try encoder.encode(
        PublicFirehoseIdentityMaterial(did: did, handle: handle, time: time)
      ),
      carBytes: nil
    )
    let account = LifecycleEventItem(
      sourceKey: PublicFirehoseSourceKey.account(did: did, operationID: operationID),
      kind: .account,
      payload: try encoder.encode(
        PublicFirehoseAccountMaterial(did: did, active: true, status: nil, time: time)
      ),
      carBytes: nil
    )
    let batch = try await control.enqueueLifecycleEventBatch(
      did: did, operationID: operationID, items: [identity, account], now: now
    )
    try await enqueueHeadSync(
      did: did,
      sourceKey: PublicFirehoseSourceKey.syncActivation(did: did, operationID: operationID),
      lifecycleGeneration: batch.generation,
      now: now
    )
  }

  public func emitRotationIdentity(
    did: String, plcOperationCID: String, handle: String?, now: Date
  ) async throws {
    let time = PublicFirehoseTime.encode(now)
    let identity = LifecycleEventItem(
      sourceKey: PublicFirehoseSourceKey.identity(did: did, plcOperationCID: plcOperationCID),
      kind: .identity,
      payload: try JSONEncoder().encode(
        PublicFirehoseIdentityMaterial(did: did, handle: handle, time: time)
      ),
      carBytes: nil
    )
    _ = try await control.enqueueLifecycleEventBatch(
      did: did, operationID: plcOperationCID, items: [identity], now: now
    )
  }

  public func emitReactivationSync(did: String, operationID: String, now: Date) async throws {
    let generation = try await control.currentLifecycleGeneration(did: did)
    try await enqueueHeadSync(
      did: did,
      sourceKey: PublicFirehoseSourceKey.syncReactivation(did: did, operationID: operationID),
      lifecycleGeneration: generation,
      now: now
    )
  }

  public func emitManualSync(did: String, requestUUID: String, now: Date) async throws {
    let generation = try await control.currentLifecycleGeneration(did: did)
    try await enqueueHeadSync(
      did: did,
      sourceKey: PublicFirehoseSourceKey.syncManual(did: did, requestUUID: requestUUID),
      lifecycleGeneration: generation,
      now: now
    )
  }

  private func enqueueHeadSync(
    did: String, sourceKey: String, lifecycleGeneration: Int64, now: Date
  ) async throws {
    guard let account = try await accounts.publicFirehoseAccountDatabases()
      .first(where: { $0.did == did }) else {
      throw PublicLifecycleEmitterError.accountUnavailable(did)
    }
    guard let state = try await account.database.loadPublicRepositoryState() else {
      throw PublicLifecycleEmitterError.missingRepositoryHead(did)
    }
    guard let commitBytes = try await account.database.block(for: state.commitCID) else {
      throw PublicLifecycleEmitterError.missingCommitBlock(did)
    }
    let car = try await PublicFirehoseDiffCAR.commitOnly(
      commitCID: state.commitCID, commitBytes: commitBytes
    )
    let material = PublicFirehoseSyncMaterial(
      did: did,
      rev: state.revision,
      commitCID: state.commitCID.string,   // adjust if CID's string accessor is throwing
      time: PublicFirehoseTime.encode(now)
    )
    _ = try await account.database.enqueuePublicFirehoseEvent(
      sourceKey: sourceKey,
      kind: .sync,
      lifecycleGeneration: lifecycleGeneration,
      payload: try JSONEncoder().encode(material),
      carBytes: car,
      now: now
    )
  }
}
```

`run()` shape (single loop, no timers inside transactions, HTTP strictly outside the store calls). Structure it like the retention service's sleep loop plus a hub forwarder task that flips an actor-held `sequencedSinceLastPass` flag — do NOT race an `AsyncStream` iterator across child-task boundaries:

```swift
private let pollInterval: Duration  // set in init: min(updateThrottle, .seconds(60))

public func run() async throws {
  let (stream, finish) = await hub.subscribeWithFinish()
  let signal = AnnounceSignal()  // small actor: setDirty() / consumeDirty() -> Bool
  let forwarder = Task {
    for await _ in stream { await signal.setDirty() }
  }
  defer {
    forwarder.cancel()
    finish()
  }
  try await announcePass(now: Date(), sequenced: false)
  while !Task.isCancelled {
    try await Task.sleep(for: pollInterval)
    let sequenced = await signal.consumeDirty()
    try await announcePass(now: Date(), sequenced: sequenced)
  }
}
```

`announcePass(now:sequenced:)` reads `crawlAnnouncerStates()` once and, for each configured crawler, announces when its **eligibility rule** holds, then records the outcome. Eligibility (this precise rule is what the three tests pin — a successful announce must NOT suppress later update-triggered announces for 24 h, and a failing crawler must NOT be hammered on every sequenced event):

- never attempted (`nextAttemptAt == nil`): eligible (covers startup).
- failure backoff pending (`attempts > 0`): eligible only when `now >= nextAttemptAt` — binds for startup, sequenced, and periodic passes alike.
- healthy (`attempts == 0`): eligible when `now >= nextAttemptAt` (the 24 h refresh) OR (`sequenced` AND `now - lastAttemptAt >= updateThrottle`).

Outcomes: on success, `recordCrawlAnnounceOutcome(origin:success:true, now:, nextAttemptAt: now + refreshInterval)`. On `false` or a thrown transport error: failure — backoff `min(3600, 30 * pow(2, min(Double(attempts), 7)))` seconds jittered by `Double.random(in: 0.8...1.2)`, log at warning with the origin, and never let a transport failure escape `run()`.
