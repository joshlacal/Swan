### Findings the adversarial pass overturned

**F22 — "CRLF injection into the outbound OAuth request line", first pass HIGH, adversarially REFUTED. I side with the refutation.** I re-verified it independently rather than taking it on trust:

- All four transports configure the pipeline with a bare `try channel.pipeline.syncOperations.addHTTPClientHandlers()` — `Sources/SwanOAuth/NIOPeerPinnedOAuthDocumentTransport.swift:91`, `Sources/SwanOAuth/SwanProxyHTTPTransport.swift:284`, `Sources/SwanOAuth/NIOPeerPinnedOAuthPostTransport.swift:162`, `Sources/SwanAccounts/NIOPeerPinnedATHandleHTTPTransport.swift:114`. Swan never passes `enableOutboundHeaderValidation: false` anywhere.
- Every public overload funnels into `_addHTTPClientHandlers` at `.build/checkouts/swift-nio/Sources/NIOHTTP1/HTTPPipelineSetup.swift:643-650`, whose `enableOutboundHeaderValidation` defaults to `true`; both the fast path (`:684-688`) and the fallback (`:707-709`) insert `NIOHTTPRequestHeadersValidator()`.
- That handler is a `ChannelOutboundHandler` that validates the **URI**, not just headers: `.build/checkouts/swift-nio/Sources/NIOHTTP1/HTTPHeaderValidator.swift:33-40` fails the promise on `!uriOnlyContainsAllowedCharacters(head.uri)` and returns **without** calling `context.write`. The allow-list at `:54-127` is ALPHA / DIGIT / `-._~` / gen-delims / sub-delims / `%` only; its own comment names CR, LF and NUL rejection as the point. The validator is added tail-most of the three handlers, i.e. it runs before `HTTPRequestEncoder` on the outbound path.

So the PoC (`%0d%0aX-Injected:%20yes`) throws at `writeAndFlush(...).get()` and zero bytes reach the socket. There is no request-line injection, no header injection, no smuggling. What actually remains is a **same-origin request-target rewrite**: bytes inside NIO's allow-list still decode through `url.path` (`%2F`→`/`, `%3F`→`?`, `%3A`→`:`), so `https://h/a%2Fb` is fetched as `/a/b`. `validateResponseIdentity` (`Sources/SwanOAuth/OAuthClientMetadata.swift:241-246`) requires the fetched document's `client_id` to equal the requested URL byte-for-byte, so metadata confusion is blocked on top of that. Real severity **low**; keep the one-line `percentEncodedPath` fix for consistency with the sibling at `SwanProxyHTTPTransport.swift:215-229`, drop the "extract a helper + new suite + high priority" framing.

**F05, F09, F19 — adversarially upheld.** I side with the first pass on all three, and on F05 I side with the *escalation* to high. The decisive fact for F05 is the charge/refund asymmetry across the WebSocket upgrade: `AvailableConnectionsHandler` charges in `channelRead` and refunds only from `channel.closeFuture` (`.build/checkouts/hummingbird/Sources/HummingbirdCore/Server/AvailableConnectionsHandler.swift:96-113`), and once full it stops calling `context.read()` on the accept socket (`:116-121`). An upgraded socket never closes, so 256 responsive-idle anonymous subscribers halt `accept()` for the whole public listener. Two corrections that do not rescue it: the management listener is a separate `Application` with its own budget (`Sources/SwanHTTP/SwanManagementHTTP.swift:36, 440-441`), so admin survives; and already-established connections keep working, so the federation damage is on relay *reconnect*.

**F30 — REFUTED, and the refutation is correct.** The codec's conversion phase genuinely does not advance depth through objects (`Sources/SwanPublicRepository/PublicRepositoryRecordCodec.swift:107, 130, 141, 183, 193`), but every feeder is depth-capped upstream: HTTP writes by `StrictPermissionedWriteJSON.validate` at `Sources/SwanHTTP/SwanPublicRepositoryMutationXRPC.swift:596` (parser at `Sources/SwanHTTP/SwanSpaceXRPC.swift:1167-1263`, depth gate `:1187`, advancing for **both** containers at `:1191-1192`), and stored-block reprojection by `RepositoryMSTValidation` (`:659`, `:663`). Residual is a maintainability inconsistency plus zero test coverage of the load-bearing gate.

## 2. Reachable today on swan.place

Short list. Seventeen findings are reachable on the deployed configuration; **ten** of those are medium or above, and only **three** are high. Everything in C2 (commitment binding), C3 (space credential revocation), C4 (service JWT), C5 (registerNotify), and most of C8/C11/C12 is gated behind configuration flags that are not set, or behind a second local account that does not exist.

**High — anonymous, no account, no cost:**

1. **F05 — `subscribeRepos` has no admission at all.** `publicFirehoseUpgradeDecision` (`Sources/SwanHTTP/PublicFirehoseStreamingRoute.swift:177-210`) is purely syntactic; there is no router middleware anywhere (`Sources/SwanHTTP/SwanHTTP.swift:759` builds a bare `Router`); the hub inserts unconditionally (`Sources/SwanHTTP/PublicFirehoseWakeupHub.swift:66`). 256 responsive-idle sockets (default at `SwanHTTP.swift:132`, never overridden — `Sources/swan/SwanCommand.swift:3040-3045`) stop the public listener accepting anything: login, OAuth, public reads, permissioned routes, and the relay's reconnect. Cloudflare's `/xrpc/*` rule explicitly excludes subscribeRepos, and WebSockets proxy 1:1 anyway.
2. **F09 — eight slow origins starve every outbound OAuth document fetch.** `OAuthRemoteFetchAdmission.shared` is a process-global non-queueing 8-slot gate (`Sources/SwanOAuth/OAuthRemoteFetch.swift:474-496`) reached pre-authentication from PAR at `Sources/SwanHTTP/SwanOAuthAuthorizationServerHTTP.swift:233`. `/oauth/token` (`:540`) and `/oauth/revoke` (`:645`) call `revalidate` with `bypassCache: true` (`Sources/SwanOAuth/OAuthClientMetadataLoader.swift:349-351`), so starvation denies the real account's token refresh, not just new client onboarding. Cost: ~1.6 req/s.
3. **F19 — 8,192 attacker `client_id`s poison the freshness table for an hour each.** The ticket is committed **before** the fetch (`OAuthClientMetadataLoader.swift:286-294` then `:296`), `retain_until = now + 3600` (`Sources/SwanSQLite/OAuthControlStore.swift:1235-1237, :201`), the cap is 8,192 (`:116-117`), and `purgeExpiredLocked` (`:1529-1541`) cannot delete a never-published row before the hour is out. There is no abandon path — grep confirms three writers total. ~2 minutes to fill at 60 req/s, ~2.3 req/s to hold. Combined with `revalidate` on every grant, this eventually locks out the one real account's client, not just strangers.

All three land on `/oauth/*` or the WebSocket route, i.e. **outside** the Cloudflare `/xrpc/*` rate-limit rule.

**Medium, reachable today:**

4. **F06** — PAR durably claims a DPoP jti before any client identity exists (`SwanOAuthAuthorizationServerHTTP.swift:215` → `Sources/SwanOAuth/OAuthProofValidation.swift:117-119` → `Sources/SwanSQLite/OAuthControlStore.swift:1741-1797`), unauthenticated, on an unrate-limited route.
5. **F41** — `handleAttempts` (10) equals `pairAttempts` (10) at `Sources/SwanAccounts/AccountLoginAdmission.swift:25-28`, so the handle-wide bucket adds zero brute-force protection against a single IP while granting that single IP a permanent global lock on the account at ~0.03 req/s.
6. **F26** — unauthenticated public-mutation bodies take a lease from the shared JSON-write pool (8 concurrent, `Sources/SwanStorage/PublicRepositoryReadDirectory.swift:731-741`) and hold it across body collection *and* authorization (`Sources/SwanHTTP/SwanPublicRepositoryMutationXRPC.swift:588-605`, `Sources/SwanHTTP/SwanJSONWriteBody.swift:293-297`). The same pool serves the AppView pipethrough. `uploadBlob` in the same file already does it correctly at `:77-79`.
7. **F11** — `maxFrameSize: 5_000_000` (`SwanHTTP.swift:1171`) is inbound-only; the drain loop at `PublicFirehoseStreamingRoute.swift:338` accepts and discards every client frame, letting each socket pin ~5 MB in the decoder's accumulation buffer at a byte per second. The doc comment at `SwanHTTP.swift:1159-1166` is factually wrong and will talk the next reader out of the fix.
8. **F37** — `emitActivation` and `emitReactivationSync` (`Sources/SwanSQLite/PublicLifecycleEmitter.swift:69-78, 99-108`) enqueue head-sync rows outside the `withActiveAccountFirehoseAuthorization` fence that `emitManualSync` uses at `:113`, so a raced deactivation can publish `#sync` after `#account(active:false)` on a firehose federated with bsky.network. The deterministic-race test exists for the fenced path only (`Tests/SwanSQLiteTests/PublicLifecycleEmitterTests.swift:375-409`).
9. **F18** — `PublicFirehoseCommitFence` deliberately re-runs the mutation after the active-account fence rejects it (`Sources/SwanSQLite/SQLitePreMigratedAccountDirectory.swift:2663-2666`). The signing-generation half is preserved and tested; the lifecycle half is a knowing waiver with no test.
10. **F21** — `public_repository_blocks` (`Sources/SwanSQLite/SwanSQLite.swift:434-437`) has no GC anywhere in the tree; dead MST and record blocks accrue during ordinary posting, no attacker required.

**Low but live:** F07 (no `id` binding on fetched DID documents), F15 (AppView proxy token signs across an unfenced keystore await, on the highest-QPS route), F22 (path rewrite, see above), F33 (unthrottled anonymous open/close journal writes), F35 (upstream `Location` relayed verbatim; the real shape is a same-origin onward-request steer, not an open redirect, because the route needs a DPoP-bound token), F40 (proxy sender resolves DNS outside any deadline while holding a pipethrough lease), F43 (256 MiB blob upload adopts with no post-stream lifecycle check).

That is why the global caps, not per-principal quotas, are the load-bearing controls in L1 and L2.

## 5. Deliberately not fixing

**Refuted.**

- **F30 (record codec nesting).** Every feeder is depth-capped before the codec: `StrictPermissionedWriteJSON` at 64 for both containers on all HTTP writes, `RepositoryRecordBlockValidator` for stored blocks. Not a security control bypass. The codec hardening in L11 is consistency work, and the tests are the part with value.
- **F22 as filed (CRLF injection).** NIO's `NIOHTTPRequestHeadersValidator` is installed by default on every one of Swan's four client pipelines and rejects any URI byte outside the RFC 9112 request-target grammar before the encoder runs. Forcing a refresh per verification would hand a remote bearer token a network-amplification primitive. Documented in L13, not coded.
- **F08 (mint-race).** Strictly subsumed by F03. An attacker who wins the race gets a credential identical to one obtainable microseconds earlier that stays valid 2 h regardless. If F03's watermark lands, F08 closes for free; if F03 is deferred, the proportionate standalone fix is one extra policy read between `SpaceCredentialAuthority.swift:743` and `:744` — do not hold a transaction across the keystore read, which is precisely what the comment at `SQLitePreMigratedAccountDirectory.swift:609-613` avoids.

Sequence after F21.
