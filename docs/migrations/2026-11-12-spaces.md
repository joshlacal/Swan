# November 12 permissioned Spaces migration

This change moves Swan from the October 29 Spaces wire (`permissioned-data-0016-2026-10-29`, reference `5d88b414a98de1ada22c94c78fa0667a7028163c`) through November 5 to the November 12 alpha (`permissioned-data-0016-2026-11-12`, reference `d4def6e9f521896ed8222f576d54923d00b5fbeb`). The proposal is pinned at `b54ec6853bab77edd4fd373804a480633094b324`. Historical profiles remain byte-for-byte verification fixtures.

## Wire cutover

November 5 adds STAR control framing: every pair starts with `0x01` and the archive ends with `0x00`. Readers also enforce 64 KiB metadata, 4 KiB keys and 1 MiB values. The old framing is not accepted. November 12 changes the archive content type to `application/vnd.dasl.star` and renames a space-meta writer's `rev` field to `repoRev`. Re-export old repository and space-meta archives from an upgraded host before importing them.

November 12 also makes these clean renames:

- `getSpaceCredential` → `authorizeSpaceSync`, `listRepos` → `listWriters`
- `notifyWrite` → `notifyRepoUpdate`, `notifyCredentialRevoked` → `notifyCredentialsRevoked`
- `memberspace.putMember` / `removeMember` → `putMembers` / `removeMembers`
- `managedspace.checkUserAccess` → `checkAccess`

The member mutations are batched. `listWriters` returns typed `repoWrite` or `repoRemoved` entries, and `listRepoOps` returns a commit on every page. `registerNotify`, `unregisterNotify` and `notifySpaceDeleted` are removed; registration now rides on `authorizeSpaceSync`, with `confirmRegistration` and `notifySpaceUpdate` handling the new flow. Space declarations use `title` rather than `name`, and named OAuth scopes use `spaceType` rather than `type`.

Space-credential signatures are selected by the `atproto-space-credential` signature tag rather than by label. Response MACs are RFC 9421 HTTP Message Signatures using `hmac-sha256` and a per-request HPKE export-only P-256 secret. The old MAC headers and derivation are not accepted.

## Stored state and deployment

Account schema v30 records writer removals and the new notification registrations. The migration preserves accounts and repository data, but drops the retired registration format, pending October 29 deletion notices, and pending write forwards; syncers must reauthorize with their `notify` registration. Back up the service before first opening existing databases with this build.

Rolling back the binary to v29 does not restore those dropped rows. It also loses every November 12 registration and queued notice, and makes removed writers appear live again because v29 does not understand the v30 removal tombstones. Restore the pre-upgrade backup before running a v29 binary.

Deploy the server, syncers, managing apps, repository hosts and migration peers together: the old method names, STAR framing, notification flow and MAC format are intentionally unsupported. Keep the producing executable with every snapshot; older snapshots restore only with their producing build. New snapshots use `--profile-id permissioned-data-0016-2026-11-12`.

## Profile and generation

`Profiles/permissioned-data-0016-2026-11-12.json` pins 32 endpoints and the November 12 lexicon corpus. `Scripts/generate-space-descriptors.py` emits the package's established compact `SwanSpacesWire.swift` registry; it does not add a second full Petrel type tree. `Scripts/verify-profile.sh` verifies the profile, lexicon manifest, generated-wire manifest, Petrel manifest and immutable historical profiles without fetching the network. Swan uses the frozen November 12 backport on the old Petrel runtime line at `db6c3ccbaff9d62e84c12e9183e2dc292585fc05`; the local HPKE implementation remains until Swan moves to Petrel 2.0.
